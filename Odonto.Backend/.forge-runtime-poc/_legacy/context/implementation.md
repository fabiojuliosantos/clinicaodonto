# Implementation Context

## Purpose

Used when implementing new features, fixing bugs or extending existing functionality.

The objective is to provide all information required to produce code that is consistent with the project's architecture, coding standards and engineering philosophy.

---

## Required Context

- system.md
- engineering-philosophy.md
- architecture.md
- stack.md
- coding-style.md
- domain.md

---

## Optional Context

Load only when relevant.

- architecture-decisions.md
- workflow.md
- quality-standards.md
- glossary.md

---

## User Input

The implementation request.

Examples:

- Implement JWT authentication.
- Add patient registration.
- Create a new endpoint.
- Fix a validation bug.

---

## Expected Output

The response may include:

- implementation plan
- code
- architectural considerations
- risks
- trade-offs
- learning notes (when valuable)

The output should remain focused on the requested task.
